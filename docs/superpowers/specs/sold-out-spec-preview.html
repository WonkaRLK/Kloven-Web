Sold Out Toggle — Kloven Streetwear

✓ Aprobado por usuario 2026-05-22 v2 — revisión técnica incluida

Objetivo

Agregar un flag sold_out a nivel producto que:

  • El admin activa/desactiva con un toggle rápido desde la lista de productos (sin entrar a editar)
  • Muestra badge "AGOTADO" en la card y página de producto del storefront
  • Deshabilita el botón de carrito en la página de detalle
  • El servidor bloquea el checkout si el producto está agotado (la UI es decorativa, el API es el guardián real)
  • El producto sigue visible en la web (≠ active: false que lo oculta)

Base de datos

ALTER TABLE products
  ADD COLUMN IF NOT EXISTS sold_out BOOLEAN NOT NULL DEFAULT false;

El default false mantiene todos los productos existentes disponibles sin ninguna migración de datos.

Tipos — src/lib/types.ts

export interface Product {
  // ...campos existentes...
  sold_out: boolean;  // <-- nuevo
}

ProductWithVariants extends Product, RegularCartItem y ComboCartItem reciben el campo automáticamente.

API

Nuevo: PATCH /api/admin/products/[id]/sold-out

Endpoint liviano solo para el toggle rápido. No requiere el body completo del producto.

// Body: { sold_out: boolean }
// Requiere validateAdminAuth
// Actualiza: sold_out + updated_at
// Respuesta: objeto producto (campos de products, sin variantes)

Justificación: el PUT existente exige el producto completo + variantes. Mandar todo eso solo para un boolean es innecesario.

PUT /api/admin/products/[id]

Agregar al objeto de update:

sold_out: body.sold_out ?? false,
⚠️ El formulario de edición DEBE leer y enviar el valor actual de sold_out. Si el form no lo incluye, ?? false lo resetea silenciosamente cada vez que el admin guarda el producto.

POST /api/checkout — validación server-side

⚠️ Este es el cambio más crítico. Sin esto, un usuario puede completar el checkout aunque el producto esté marcado como agotado.
// 1. Agregar sold_out al select de productos:
.select("id, name, price, image_url, is_combo, sold_out")

// 2. En el loop de validación de items:
if (product.sold_out) {
  return NextResponse.json(
    { error: `El producto "${product.name}" está agotado` },
    { status: 400 }
  );
}

GET /api/products y GET /api/products/[slug]

Sin cambios — ya hacen select("*"), el campo nuevo llega solo.

POST /api/admin/products (crear)

Agregar sold_out: body.sold_out || false en el insert, por simetría y para no depender del default de DB.

Admin

Lista de productos (/admin/productos)

  • Columna Estado: junto a "Activo/Inactivo", mostrar badge naranja "Agotado" cuando sold_out === true
  • Toggle rápido: botón con ícono PackageX (agotado) / Package (disponible) junto a editar/eliminar
  • Al clickear: llama a PATCH .../sold-out, actualiza estado local, sin recargar la lista
  • Feedback visual con spinner durante el loading

Formulario de edición (/admin/productos/[id])

  • Toggle "Marcar como agotado" en la sección de configuración
  • Mismo estilo que otros toggles del admin (inline-flex, rounded-full)
  • Obligatorio: inicializar desde product.sold_out y enviarlo en cada PUT

Storefront — ProductCard

Badge "AGOTADO" — posicionamiento sin colisiones

La card ya tiene hasta dos badges: top-2 left-2 (descuento) y top-2 right-2 (COMBO).

SituaciónPosición AGOTADO
Solo sold_outtop-2 left-2
sold_out + descuentotop-2 right-2
sold_out + comboCOMBO en top-2 right-2, AGOTADO en top-10 right-2
sold_out + descuento + comboCOMBO en top-2 right-2, AGOTADO en top-10 right-2, descuento en top-2 left-2

Estilo: bg-gray-900 text-white, mismo tamaño que el badge de descuento.

Overlay hover

La card es un <Link> — el usuario puede seguir clickeando para ir a la página del producto (puede ver fotos y esperar restock). Solo cambia el texto del overlay:

  • Si sold_out: texto "Sin Stock" en gris, sin ícono de bolsa
  • Si no: comportamiento actual sin cambios

Storefront — Página de producto

Botón de carrito

{product.sold_out ? (
  <button
    disabled
    className="w-full py-4 bg-gray-700 text-gray-400 font-bold
               uppercase tracking-widest cursor-not-allowed opacity-70"
  >
    Sin Stock
  </button>
) : (
  // botón actual — sin cambios
)}

La selección de talle/color sigue mostrándose. El botón está deshabilitado sin importar la selección.

Combos

Si el combo tiene sold_out === true, aplica la misma lógica. La flag sold_out de los sub-productos dentro de un combo es ignorada — solo importa el flag del combo como unidad.

CartContext y carrito existente

El CartContext guarda un snapshot al momento de agregar. Si el producto se marca como agotado después, la UI del carrito no lo detecta. El server-side check en /api/checkout es el guardián autoritativo — devuelve 400 sin importar el estado del carrito del cliente.

Flujo completo

Admin entra a /admin/productos y clickea el toggle PackageX en la fila
Badge "Agotado" aparece en la tabla sin recargar
En el storefront, la card muestra badge "AGOTADO" y el overlay dice "Sin Stock"
El cliente entra al producto — puede ver fotos y talles, el botón está deshabilitado
Si el cliente tenía el producto en el carrito desde antes, el checkout devuelve error 400
Cuando llega stock, el admin clickea el toggle — el producto vuelve a estar disponible

Lo que NO cambia

  • El producto sigue apareciendo en la tienda, carousel y búsquedas
  • active: false sigue siendo el mecanismo para ocultar el producto completamente
  • El stock numérico de variantes no se modifica — sold_out es independiente
  • No hay lógica automática: el admin activa/desactiva manualmente
  • El campo on_sale no interactúa con sold_out
